# 复合剪贴板内容

一次复制对应一条记录。记录保存可恢复的格式表示（representations）和以 SHA-256 引用的图片资源（assets），并派生 `kinds`、检索文字和预览。同一内容同时提供 HTML、纯文本、位图属于替代表示，不会被拆成多条历史或凭空拼成多个内容片段。

检索文字汇总所有受支持的文本表示及文件路径，避免较短的纯文本表示遮掉其他可搜索内容。复制仍使用各自原始表示；需要合成纯文本备用格式时，仅选一个优先表示，避免粘贴出重复内容。

内容指纹忽略采集诊断，并统一缺省和空资源列表的表示；保存时若调用方提供指纹，必须与内容匹配，不能静默覆盖错误指纹。

`kind` 用于记录处理方式的分派，复合记录为 `composite`；`kinds` 表达实际包含的内容类型，例如 `["image", "table", "text"]`。网页、原生搜索、HTTP 和 MCP 使用类型成员关系筛选。按类型统计时，同一条记录可计入多个类型；总记录数及总字节数只计算一次，不应把类型分项相加得到总数。

## 采集与恢复

- 支持通用 HTML、RTF、纯文本、PNG/Windows 位图、实体文件列表，以及微信/QQ 富编辑 XML 的图文适配。
- HTML 保留文字与图片顺序、表格及被动格式；本地文件或 data URI 图片在采集时复制进记录，用内容哈希替换临时路径。不会抓取网络图片或 UNC 路径。
- 只选中表格行或单元格时补全表格上下文；纯文本备用表示保留单元格分隔。RTF 类型由解析器识别控制词，正文中的转义示例和二进制数据不会被当作图片、表格或嵌入对象。
- RTF 中的嵌入对象不重放；HTML 活动内容及外部子资源被剔除。资源不可读、超过限制或不受支持时，通过 `issues` 和界面提示说明部分保存。
- RTF 因嵌入对象被舍弃时仍保留可解码文字；HTML 没有可显示图片时，预览展示独立位图。微信/QQ 富文本恢复保留表格单元格之间的文字分隔。
- 任意私有二进制格式、OLE 对象、虚拟文件、嵌入音视频尚未实现通用恢复。其他应用能否接受某个格式，由目标应用自己的粘贴行为决定。
- 文件列表保存路径引用，不复制用户原文件；恢复前检查文件是否可用。图片资源则随复合记录完整保存。
- 单个复合包最多 64 MiB、128 个资源、5 种标准表示；采集资源预算为 32 MiB，单图还受图片配置限制。
- 普通文本、单图和同类型文件的直接处理路径仍然存在；它们是单一内容表示，不是旧模型兼容层。

## 存储与访问

数据库 schema 为 v13。复合资源随 `content_json` 存入加密数据库，`content_types` 保存由内容派生的类型和二级分类，采集与导入共用同一套生成逻辑。保存、删除和导入具有同一条记录的事务边界。JSON、加密备份使用导出版本 10，XLSX 使用版本 9；它们都携带复合包，导入时验证资源哈希、大小、类型投影和内容指纹。项目只支持当前结构，没有旧 schema 迁移或旧导出格式兼容。

列表查询在数据库中投影摘要，不向客户端返回二进制内容。完整内容仅由授权的预览、恢复、导出及外部内容读取入口提供；敏感记录和免费版可见范围检查与其他内容入口一致。敏感匹配检查所有文本表示；图片内的文字仍需后续 OCR 功能。

恢复到需要文件路径的应用时，在数据目录 `restore-assets` 下生成可重建的 PNG。最后一条引用记录删除或清理后，相应恢复缓存会被删除。删除记录后，之前仍引用该文件的剪贴板内容也可能失效。

网页预览使用重新生成的受限 HTML，不直接执行保存的原始标记。文件列表在同一张卡片及详情中单独列出，不因存在文字或 HTML 而被隐藏，也不重复作为纯文本回退显示。网页复制通过本机接口恢复全部受支持格式，原生弹窗使用同一个恢复函数。HTTP 内容端点和 MCP 内容读取对复合记录返回 JSON 包；列表返回 `kinds`、格式摘要及诊断信息。

## 验收范围

回归覆盖：临时路径变化后的重复判断、资源去重和篡改拒绝、混合文件类型、逐类型检索和统计、缺失资源降级、HTML 预览隔离、敏感访问拒绝、JSON/XLSX/内存导入往返、CF_HTML 偏移、微信/QQ 恢复表示及恢复缓存删除。

恢复测试只准备数据，不覆盖系统剪贴板。跨应用实际粘贴，特别是第三方软件的私有格式变化，仍需要在对应版本中验证。

边界回归还覆盖超过 Excel 单元格长度的中文/emoji 复合包往返、多类型筛选的排除与集合操作、敏感权限下的类型聚合、共享恢复资源最后引用删除、损坏恢复缓存重建，以及直接和合成纯文本表示的 UTF-16 恢复大小限制。
